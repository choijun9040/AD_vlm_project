계획 대비 주요 변경사항

① 핵심 증류 손실: 공간·시간 Feature 증류(L_spatial + L_temporal)를 핵심 기여로 확정. L_spatial은 attention map MSE의 스케일 문제(0.0004 수준)를 cosine similarity 기반 손실로 해결 — 스케일과 무관하게 0~2 범위가 보장되어 L_task와 균형 조정 가능.

② L_temporal 비대칭 설계: Teacher만 멀티프레임(과거 K프레임)을 보고, Student는 단일 프레임만 입력받아 Teacher의 시간적 이해를 모방. Student의 추론 비용이 늘지 않아 엣지 배포 목표와 정합.

③ Teacher FT 방식: Full Fine-tuning → LoRA FT (A100 1장 환경). loss 0.54로 충분한 성능 달성.

④ Student 모델 크기: 3B 단일 실험 (0.5B/1B/1.8B 스케일링은 시간 관계상 제외). ⑤ 배포 타겟: Jetson AGX Orin → Jetson Orin Nano (8GB).

⑥ 평가 축 확정: DriveLM은 공식 val/test 정답을 비공개(q_only)하며 챌린지 리더보드도 2024.6 마감·후속 대회 없음이 확인됨. 이에 따라 NuScenes-QA val(11,309개, scene-level held-out)을 메인 정량 평가축으로, CODA-LM을 제2 정량축(zero-shot)으로 확정. DriveLM val(q_only)은 정성 비교에만 사용.

⑦ KD-only 하이퍼파라미터 재보정 (신규): Hinton식 KD temperature(T=2~4)는 ~1,000클래스 기준 설계라, 152K 토큰 vocab에 그대로 적용하면 target 분포가 균등분포로 뭉개져 EOS 학습이 붕괴함을 확인. kd_temperature를 4.0 → 1.5로 낮춰 해결 — 대형 vocab을 가진 VLM에 output-KD를 적용할 때 일반적으로 유의해야 할 지점으로 논문에 기술 가치 있음.

⑧ SOTA 비교 프로토콜 통제 (신규): EM-VLM4AD 원 저자 설정(6카메라뷰, max_length=512)이 우리 student(단일뷰, max_new_tokens=16)보다 입력 정보량·생성 여유가 유리함을 발견 — --single_camera/--max_length 통제 옵션을 추가해 공정 비교로 재실행.

연구 동기 및 핵심 Gap 분석
현재 자율주행 VLM 연구는 세 가지 접근법이 존재하는데, 각각 명확한 한계가 있습니다.
접근법 ①: 대형 VLM 직접 사용 → 추론 시 제거

DiMA (CVPR 2025), VLM-AD (CoRL 2025), RSD (2025)

대형 VLM(7B+)을 teacher로 사용하여 vision planner에 지식을 증류하고, 추론 시에는 VLM을 완전히 제거합니다. DiMA의 경우 MLLM의 중간 feature와 surrogate task를 통해 vision planner를 강화하고, VLM-AD는 VLM이 생성한 자연어 추론을 보조 학습 신호로 활용합니다. RSD는 위험 의미 증류를 통해 BEV 표현을 강화합니다.

한계: 추론 시 자연어 출력 능력이 완전히 사라짐. 장면 설명, VQA, 위험 상황에 대한 자연어 설명 등 언어 기반 상호작용이 불가능.

접근법 ②: 처음부터 경량 VLM 설계

EM-VLM4AD (2024), PeLiC-VLM (2026), MiniDrive (2024)

경량 LLM 백본(T5-Base 235M, 또는 268M 급)에 직접 자율주행 데이터를 학습시킵니다. PeLiC-VLM은 AGX Orin에서 43ms 추론을 달성했고, EM-VLM4AD는 메모리를 10배 절감했습니다.

한계: 대형 VLM이 가진 풍부한 세계 지식(world knowledge)과 추론 능력을 체계적으로 전이받지 못함. 작은 모델을 처음부터 학습하므로 long-tail 시나리오에서의 일반화 능력이 제한적.

접근법 ③: 산업계 — 대규모 증류 후 차량 탑재

Li Auto VLA (2025), Waymo Foundation Model (2025)

Li Auto는 32B VL 모델을 3.6B로 증류하여 차량에 탑재하고, Waymo는 Teacher-Student 구조로 대형 모델의 능력을 온보드 모델로 전이합니다. 이들은 사내 대규모 데이터와 수천 GPU-hours를 활용합니다.

한계: 학술 환경에서 재현 불가능한 규모. 논문으로 공개된 방법론이 제한적.

본 연구가 채우는 Gap: 접근법 ①과 ②의 교집합에 위치합니다. 대형 VLM의 풍부한 지식을 자율주행 도메인에 특화된 증류 전략으로 소형 VLM에 전이하되, Student가 여전히 완전한 VLM이므로 추론 시에도 자연어 기반 장면 이해·VQA·위험 설명이 가능합니다. 동시에 접근법 ③의 아이디어를 학술적으로 재현 가능한 규모(0.5B–2B, 단일 A100)로 축소하여 체계적으로 연구합니다.

연구 질문 (RQ) 정립
RQ1 — 증류 전략의 효과

공간·시간 Feature 증류는 출력(logit) KD보다 얼마나 효과적인가?

공간 정보 보존 증류(Spatial-Preserving Feature KD)와 시간적 맥락 압축 증류(Temporal Context KD) 각각이 표준 출력 KD 대비 자율주행 VQA, 장면 캡셔닝, 위험 장면 대응 성능에서 어느 정도의 이득을 가져오는지를 정량적으로 검증합니다. 특히 "어디에 있는가"(spatial)와 "어떻게 변하는가"(temporal)라는 자율주행 고유의 요구가 출력 분포 모방만으로는 전이되지 않음을 보이는 것이 핵심입니다.

RQ2 — 모델 크기 vs 성능 임계점

자율주행 VLM의 critical size threshold는 어디인가?

Teacher(7B) → Student(3B → 1.8B → 1B → 0.5B)로 크기를 줄여갈 때, 각 태스크별 성능 저하 곡선의 형태를 분석합니다. 특히 위험 상황 탐지는 어느 크기에서 급격히 무너지는지, 일반 VQA는 상대적으로 어느 크기까지 견디는지 등 태스크별 민감도 차이를 규명합니다.

RQ3 — 엣지 실시간 실현 가능성

증류 + 양자화된 VLM이 Jetson Orin Nano에서 실시간 추론 가능한가?

INT4/INT8 양자화와 TensorRT 최적화 후, 목표 latency(≤100ms/frame, 즉 ≥10 FPS)를 달성할 수 있는 최대 모델 크기는 무엇인지, 그때의 성능 저하는 어느 수준인지를 검증합니다. 양자화에 의한 성능 손실과 증류에 의한 성능 보존 효과의 상호작용도 분석합니다.

실제 구현 변경사항: Teacher는 LoRA Fine-tuning으로 학습했습니다 (A100 1장 환경 제약). 증류 손실은 공간·시간 Feature 증류(L_spatial + L_temporal)로 구성하며, L_spatial은 cosine 정규화로 스케일 문제를 해결하고 L_temporal은 비대칭 구조(Teacher 멀티프레임 / Student 단일 프레임)로 설계했습니다. 배포 타겟은 Jetson AGX Orin → Jetson Orin Nano (8GB)로 변경했습니다.

Stage 1 — Teacher LoRA Fine-tuning

DriveLM (메인) + NuScenes-QA (보강)

DriveLM: Perception → Prediction → Planning Graph VQA로 Teacher가 자율주행 추론 체계를 학습하는 메인 데이터.

NuScenes-QA: 460K QA 쌍의 규모로 학습 데이터를 보강. 존재·개수·상태·관계 등 세분화된 3D VQA를 포함하여 Teacher의 공간 이해력 강화.

학습 방식: A100 1장 환경에서 LoRA Fine-tuning 수행 (1 epoch, avg_loss 0.54). WeightedRandomSampler로 DriveLM:NuScenes-QA = 4:6 비율 샘플링.

DriveLM의 구조적 특성 활용

Patch 구조 + 시간 순서 구조가 L_spatial·L_temporal의 소스

공간(patch) 구조: 현재 프레임(CAM_FRONT) 이미지가 vision encoder에서 patch 단위 feature로 표현됨 — 이 patch-level 공간 구조가 L_spatial의 증류 소스. 배포 환경(전방 카메라 단일 뷰)과의 정합성을 위해 멀티뷰(6방향 카메라)는 사용하지 않고, 멀티뷰 확장은 future work로 남김.

시간 순서: scene_token → key_frames 구조가 시간 순서를 보존 (키프레임 간격 평균 약 3.1초) — 과거 K−1프레임 + 현재 프레임 시퀀스를 구성해 L_temporal의 Teacher 멀티프레임 입력으로 활용.

새로운 데이터 수집 없이, 기존 데이터에 이미 존재하지만 활용되지 않던 구조를 증류 신호로 전환하는 접근입니다.

Stage 2 — Spatio-Temporal Distillation (2개 데이터 동시 사용)

통합 DataLoader에서 3가지 Loss에 각각 매핑

하나의 DataLoader에서 배치를 뽑되, DriveLM 샘플은 scene 내 시간 순서 정보(과거 프레임)를 함께 제공합니다.

DriveLM + NuScenes-QA → L_task (ground truth 직접 학습: VQA cross-entropy, 모든 실험 공통)
현재 프레임(CAM_FRONT) patch feature → L_spatial (Teacher vision encoder 중간층 feature를 cosine 손실로 모방 — 스케일 문제 해결)
DriveLM scene 시퀀스 → L_temporal (Teacher만 과거 K프레임 입력, Student는 단일 프레임으로 Teacher hidden state 정렬 — 비대칭 구조)

점진적 ablation: ① Baseline(L_task) ② KD only(L_task+L_kd) ③ +L_spatial ④ +L_temporal ⑤ Full(L_task+L_spatial+L_temporal)

Stage 3 — 평가 (최종 확정 구성)

메인 정량 · 제2 정량 · 정성 비교의 3축 체계

메인 정량축 — NuScenes-QA val (11,309개): nuScenes 공식 train/val이 scene 단위로 분리되어 있어 5개 모델 모두에게 진짜 held-out. 정답이 짧은 폐집합 문자열(yes/no·객체명·상태·숫자)이므로 공통 정규화 후 exact-match Accuracy를 전체 + 카테고리별(exist/object/status/count/comparison)로 측정. 공간 관계 유형에서 L_spatial 효과, 상태·이동 유형에서 L_temporal 효과를 직접 확인. bootstrap 신뢰구간 + 모델 쌍별 유의성 검정 병행.

제2 정량축 — CODA-LM (zero-shot): 학습 도메인(nuScenes)과 완전히 분리된 코너케이스(도로 위 이물질, 전복 차량 등)에서 General/Regional Perception + Driving Suggestion 정량 평가. 텍스트 지표(BLEU/CIDEr)를 기본으로 하고, judge 기반 프로토콜은 비용/재현성을 검토 후 병기. 단일 평가축 의존을 줄이고 일반화 주장을 뒷받침.

정성 비교 — DriveLM val (q_only, 799 키프레임): 정답이 비공개이므로 채점은 불가하지만, 동일 질문에 대한 5개 모델의 답변을 side-by-side로 제시하는 정성적 사례 분석에 활용 (비용 거의 0).

DriveLM 공식 평가 불가 사유 (확인 완료): DriveLM은 val/test의 정답을 공개하지 않으며(배포 파일명부터 v1_1_val_nus_q_only.json), 공식 채점 경로였던 CVPR 2024 Autonomous Grand Challenge 리더보드는 2024년 6월 마감·후속 대회 없음이 확인됨. EM-VLM4AD 등 선행 논문들의 "DriveLM 점수"도 대부분 저자 자체 train split 분할 점수이며, 해당 split의 scene은 본 연구의 학습 데이터에 이미 포함되어 재사용 불가. 이에 따라 위 3축 체계로 평가를 확정.
핵심: DriveLM train은 학습의 핵심 축(L_task + L_spatial patch feature + L_temporal 시퀀스 소스), NuScenes-QA는 학습 보조이자 메인 정량 평가축(val, scene-level held-out), CODA-LM은 zero-shot 제2 정량축, DriveLM val(q_only)은 정성 비교. 학습·평가가 nuScenes 공식 scene split을 그대로 따르므로 L_temporal의 시퀀스 학습에도 train/val 오염이 없음.

증류 손실 함수 상세 설계
전체 손실은 3가지 항으로 구성됩니다. L_spatial과 L_temporal이 본 연구의 핵심 기여입니다.
구현 손실 함수:
L_total = L_task + λ_s · L_spatial + λ_t · L_temporal

L_spatial: attention map MSE의 스케일 문제(0.0004 수준)를 cosine similarity 기반으로 설계하여 해결
L_temporal: TAM 풀 스펙 대신 비대칭 구조(Teacher 멀티프레임 / Student 단일 프레임)로 설계 — Student 추론 비용 불변
Loss ① — Spatial-Preserving Feature KD (핵심 기여 1)

공간 정보 보존 Feature 증류 (Cosine + 경량 정렬 head)

핵심 아이디어: 자율주행에서는 "무엇이 있는지"만큼 "어디에 있는지"가 중요합니다. 현재 프레임(CAM_FRONT)에 대한 Teacher vision encoder의 patch-level feature를 Student가 모방하도록 손실을 설계하되, 기존 MSE의 스케일 소실 문제를 cosine 기반으로 해결합니다.

기존 문제와 해결:
MSE(A_T, A_S) ≈ 0.0004 — L_task(~0.6) 대비 기여가 사실상 0
→ L_spatial = 1 − cos(h_T, proj_s(h_S)) — 항상 0~2 범위 보장, λ_s 튜닝만으로 균형 조정 가능

구체적 방법:
1) Teacher(7B)와 Student(3B)의 vision encoder 중간층(layer 23)에서 forward hook으로 hidden state 추출 — Qwen2.5-VL 계열은 3B/7B가 동일한 vision encoder 구조(hidden dim 1280, depth 32)를 공유하므로 동일 인덱스에서 추출
2) 경량 정렬 head proj_s: nn.Linear(1280, 1280)를 Student 쪽에 추가 (학습 가능, 추론 시 제거) — 차원이 같아도 독립적으로 사전학습된 두 인코더의 feature 공간이 선형 정렬되어 있다는 보장이 없어, "공간 정렬"은 projection이 전담하고 LoRA는 "표현 조정"에 집중하도록 역할 분담 (FitNets 계열 feature-KD의 표준 설계). 이때 Student vision tower의 학습 경로는 vision attention(qkv/proj)에 확장 적용한 LoRA(lora_target_vision_attn=True)가 담당 — 기본 LoRA target은 LLM 모듈 기준이므로 vision 쪽은 명시적 확장이 필요
3) 패치(토큰) 단위 cosine similarity를 최대화 — Teacher가 멀티프레임을 입력받아도 vision encoder는 이미지를 독립 처리하므로, 현재 프레임의 feature만 슬라이싱해 비교

실증 관찰: projection 없이 직접 정렬 시 loss가 450스텝 동안 정체(0.438→0.437)했으나, 정렬 head 추가 후 뚜렷한 가속 하강(1.000→0.956, 350스텝)을 확인 — 동일 아키텍처 계열이라도 feature 공간의 선형 정렬 장치가 필요함을 실험적으로 확인. vision LoRA와 projection 양쪽 그래디언트가 모두 nonzero로 유지되어 한쪽에 일이 쏠리는 퇴화 없음.

직관: 출력 KD는 "최종 답"만 모방시키지만, feature KD는 "장면을 보는 방식"(객체의 위치 관계 표현)을 전이합니다. 배포 환경(전방 카메라)과의 정합성을 위해 단일 뷰로 설계하며, 멀티뷰(6방향) 확장은 future work.

Loss ② — Temporal Context KD (핵심 기여 2)

시간적 맥락 압축 증류 (비대칭 Teacher-Student 구조)

핵심 아이디어: Teacher는 학습 시 과거 K개 프레임을 함께 보고 시간적 맥락(차량 이동 방향, 보행자 궤적)을 이해합니다. Student는 단일 프레임만 입력받으면서도 Teacher의 멀티프레임 이해를 모방하도록 학습합니다.

비대칭 구조:
Teacher 입력: (frame_{t-K+1}, ..., frame_t) → h_T^{multi}
Student 입력: frame_t (단일) → h_S^{single}
L_temporal = 1 − cos(h_T^{multi}, proj(h_S^{single}))

LLM hidden dim은 3B(2048)와 7B(3584)가 다르므로, 학습 가능한 projection layer(2048→3584)로 정렬합니다 (추론 시 제거). L_spatial의 정렬 head(1280→1280)가 "동일 차원 간 공간 정렬"을 담당한다면, 이쪽은 "차원 변환 + 정렬"을 함께 수행하는 구조입니다.

왜 비대칭인가:
1) Student 추론 비용 불변 — Jetson 배포 시 단일 프레임 추론 속도 유지 (TAM 모듈, 멀티프레임 버퍼 불필요)
2) Teacher 추론은 학습 시에만 발생하므로 배포 성능에 무관
3) "단일 프레임만 보고도 시간적 맥락을 추론하는 Student"라는 스토리가 경량화 논문 취지와 정합

데이터 구성: DriveLM의 scene_token → key_frames 시간 순서 구조(키프레임 간격 평균 약 3.1초)를 활용해 (과거 K−1프레임 + 현재 프레임) 시퀀스 구성. K=2부터 시작해 A5 ablation으로 K 민감도 검증.

Loss ③ — Standard Task Loss

기본 태스크 손실 (Ground Truth 기반)

Student는 Teacher 모방만이 아닌, ground truth에 대한 직접 학습도 병행합니다.

L_task = L_VQA(cross-entropy)

VQA는 auto-regressive language modeling loss를 사용합니다. 정답 토큰 이전 구간(질문+이미지)은 -100으로 마스킹하여 답변 토큰에서만 loss가 계산됩니다.

실제 적용 손실 함수:
L_total = L_task + λ_s · L_spatial + λ_t · L_temporal

초기 설정: λ_s=1.0, λ_t=1.0 (cosine 기반이라 0~2 범위 보장, A6 ablation으로 민감도 검증)
projection: L_spatial 정렬 head 1280→1280(약 1.6M) + L_temporal projection 2048→3584(약 7.3M) — 둘 다 학습 가능하며 추론 시 제거되어 배포 모델 크기 불변
Teacher 입력 길이: 동적 패딩 — 배치 시점(collate)에 배치 내 최장 길이로 패딩 (K=2 기준 배치 평균 약 526 토큰, 고정 패딩 대비 스텝당 시간 약 18% 단축). max_length=1600은 안전망으로만 유지 (truncation 실측 0건)

ablation 실험별 CONFIG: 단독 실험은 동일 스크립트에서 설정만 변경 — +L_spatial(temporal_k=1, λ_s=1.0, λ_t=0: Teacher가 Student와 동일한 단일 프레임 입력, 데이터 파이프라인 비용도 절약) / +L_temporal(temporal_k=2, λ_s=0, λ_t=1.0) / Full(temporal_k=2, λ_s=1.0, λ_t=1.0)

양자화 및 Jetson 배포 전략
7a

Post-Training Quantization (PTQ)

증류 완료된 Student VLM(FP16)에 AWQ (Activation-Aware Weight Quantization)를 적용하여 INT4로 양자화합니다. AWQ는 MIT HAN Lab에서 개발한 방법으로, 활성화 기반의 중요도를 고려하여 양자화 오류를 최소화합니다. Jetson에서 TinyChat과 함께 사용 실적이 검증되어 있어 가장 안전한 선택입니다.

비교군: GPTQ INT4 (더 높은 압축률, 느린 양자화 속도), FP16 baseline (양자화 없음), INT8 (중간 지점)

7b

TensorRT 변환 (선택적)

Vision Encoder(ViT) 부분은 TensorRT로 변환하면 추가적인 속도 이득을 얻을 수 있습니다. LLM 부분은 TensorRT-LLM을 사용하거나, vLLM/llama.cpp 등의 최적화된 추론 엔진을 활용합니다.

주의: VLM의 Vision Encoder와 LLM을 분리 최적화한 뒤 다시 연결하는 과정에서 정확도 손실이 발생할 수 있으므로, 변환 전후 성능 비교 필수.

7c

Jetson Orin Nano 배포 환경

하드웨어: Jetson Orin Nano 8GB — GPU 1024 CUDA cores, 40 TOPS (INT8), 8GB LPDDR5 (unified memory)
소프트웨어: JetPack 6.x, CUDA 12.x
추론 프레임워크:
• llama.cpp (GGUF 포맷) — 가장 현실적. AWQ INT4 → GGUF 변환 후 CPU/GPU 혼합 추론
• MLC-LLM — VLM 지원, Orin Nano 호환

AWQ INT4 후 예상 크기: 3B 모델 약 2.0GB → 8GB 통합 메모리에서 여유 있게 동작

7d

벤치마크 측정 항목

Latency: TTFT (Time-to-First-Token), Token generation rate (tokens/sec), 전체 응답 시간 (ms/frame)
Memory: GPU 메모리 점유 (GB), peak memory
Throughput: FPS (1초에 처리 가능한 프레임 수)
Power: 전력 소모 (W) — Jetson의 여러 power mode(15W/30W/50W/MAXN) 별 비교

각 항목은 100회 이상 반복 측정 후 평균 ± 표준편차로 보고. warm-up 10회는 제외.

예상 기여점 및 한계점
예상 기여점

학술적 기여 3가지

C1. Scale-Robust Spatial Feature KD — attention map MSE의 스케일 소실 문제를 cosine 손실로, 동일 차원 인코더 간 feature 공간 불일치를 경량 정렬 head(1280→1280, 추론 시 제거)로 해결한 공간 정보 보존 증류 제안. 동일 아키텍처 계열(Qwen2.5-VL 3B/7B)조차 feature 공간이 선형 정렬되어 있지 않다는 실증 관찰 포함.

C2. Asymmetric Temporal Context KD — Teacher만 멀티프레임을 보고 Student는 단일 프레임으로 시간적 맥락을 모방하는 비대칭 증류 구조 제안. Student 추론 비용을 늘리지 않으면서 시간적 이해를 전이하여 엣지 배포와 정합.

C3. End-to-End 엣지 배포 파이프라인 — 증류된 3B Student를 AWQ INT4 양자화 후 Jetson Orin Nano에 배포하는 실용적 파이프라인 제시. 7B Teacher 대비 약 3.5x 경량화로 엣지 실시간 추론 가능성 입증.

예상 한계점

논문에서 솔직히 논의할 사항

L1. DriveLM-nuScenes 규모 한계 (~4K 키프레임). 대규모 데이터에서의 효과는 추가 검증 필요

L2. Teacher LoRA FT 사용 — Full FT 대비 성능 상한 제약 가능성

L3. Student 단일 크기(3B)만 실험 — 크기별 성능 임계점 분석 미수행

L4. L_temporal의 시간 간격이 DriveLM 키프레임 간격(평균 약 3.1초)에 의존 — 간격이 성겨 급정거 직전 등 세밀한 시간 역학은 포착이 어려우며, 더 촘촘한 프레임 시퀀스에서의 효과는 미검증

L5. DriveLM 공식 val/test 정답 비공개 + 챌린지 리더보드 마감으로 DriveLM 벤치마크 직접 채점 불가 — NuScenes-QA val을 메인 정량축으로 대체했으며, 선행 논문들과의 비교는 프로토콜 차이를 명시한 간접 비교(+동일 조건 재학습 직접 비교)로 수행

L6. Open-loop 평가만 수행. Closed-loop (CARLA 등)은 future work

L7. 단일 센서(카메라)만 사용. LiDAR 통합은 범위 외

투고 전략: 핵심 결과가 나오면 워크숍 논문(NeurIPS/ICML AD Workshop, CVPR WAD 등)에 먼저 투고하여 피드백을 받고, 보완 후 메인 학회(ECCV, AAAI, ICCV)에 투고하는 전략을 추천합니다. Drive-KD (2026)나 EvoDriveVLA (2026)이 등장하고 있으므로, 빠르게 실험을 완료하는 것이 중요합니다.

구현 시작 가이드 — 첫 2주 Action Plan
D1

Day 1–3: L_spatial 구현

Teacher/Student vision encoder layer 23에 forward hook을 걸어 patch-level hidden state 추출 (Qwen2.5-VL 계열은 vision encoder가 동일: dim 1280, depth 32). 경량 정렬 head(1280→1280)를 Student 쪽에 추가해 1 − cos(h_T, proj_s(h_S)) 손실 구현 — 차원이 같아도 독립 사전학습된 feature 공간은 선형 정렬되어 있지 않음이 실험으로 확인됨(정렬 head 없이는 loss 정체). 소규모 스모크로 하강 추세와 grad 정상 여부 검증.

D2

Day 4–6: L_temporal 데이터 파이프라인

DataLoader 확장 — DriveLM scene_token → key_frames 시간 순서로 (과거 K−1프레임 + 현재 프레임) 시퀀스 구성 (K=2부터). Teacher 멀티프레임 입력 포맷 구성 및 메모리 사용량 측정. Student는 기존 단일 프레임 입력 유지.

D3

Day 7–9: +L_spatial 학습 실행

temporal_k=1, λ_s=1.0, λ_t=0으로 학습 — Teacher가 Student와 동일한 단일 프레임 입력을 사용하므로 멀티프레임 데이터 파이프라인 비용 없이 1 epoch 학습 (~26–30시간 예상). 기존 Baseline/KD only와 동일한 하이퍼파라미터(effective batch 16, lr 2e-5) 유지하여 공정 비교 보장.

D4

Day 10–12: +L_temporal 및 Full 학습 실행

temporal_k=2, λ_s=0, λ_t=1.0(+L_temporal), 이어서 temporal_k=2, λ_s=1.0, λ_t=1.0(Full) 학습. Teacher 멀티프레임 forward는 동적 패딩(배치 내 최장 길이, max_length=1600 안전망)으로 수행하여 스텝당 시간을 절감하고, truncation 경고 발생 여부를 모니터링.

D5

Day 13–14: 5-way 평가 + SOTA 직접 비교

Baseline / KD only / +L_spatial / +L_temporal / Full 5개 모델을 NuScenes-QA val 11,309개(모델당 약 2.6시간)에서 평가 — 전체 + 카테고리별(exist/object/status/count/comparison) exact-match Accuracy로 어떤 손실이 어떤 능력을 개선했는지 매핑. 병렬로 EM-VLM4AD를 동일 데이터로 FT 후 같은 평가셋에서 zero-shot/FT 평가. 이후 CODA-LM zero-shot → AWQ INT4 양자화 → Jetson 배포로 진행.
