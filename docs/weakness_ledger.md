# 약점 원장

> **왜 이 문서가 있는가.** 약점을 극복하는 실험을 하면 새 약점이 나오는 일이 여덟 라운드
> 반복됐다. 열린 연구에는 "약점이 더 없음"이라는 고정점이 없다 — 주장이 정밀해질수록
> 검증 가능한 표면적이 늘기 때문이다. 그래서 **연구는 열어 두되 프로그램을 유계로**
> 만든다. 새로 나오는 약점은 반드시 아래 셋 중 하나로 분류하고, 분류 규칙은 고정한다.
>
> | 분류 | 뜻 | 처리 |
> |---|---|---|
> | **닫힘** | 자동 검사가 재발을 막는다 | 검사기에 규칙이 있고 회귀 시험이 검사기를 지킨다 |
> | **한계** | 알고 있으나 더 방어하지 않는다 | 9장에 적는다. 다시 논쟁하지 않는다 |
> | **열림** | 실제로 진행 중이거나 대기 | 비용과 담당(나/사용자/하드웨어)을 적는다 |
>
> 이 표가 한 페이지에 유지되면, 언제든 **무엇을 주장하고 무엇을 포기했고 무엇이 열려
> 있는지**를 말할 수 있다. 석사 논문 심사가 요구하는 것도 "약점이 없다"가 아니라 이것이다.
>
> 최종 갱신: 2026-09-15

## 주장의 핵심과 주변부

같은 무게로 방어하지 않는다. **핵심은 반박에 불변이고, 주변부는 계속 흔들린다.**

**핵심** — 더 좁힐 것이 거의 없다
- 스케일 불변성 → 직교성. **수학**이라 측정으로 무너지지 않는다
- INT8 SNR 역전, 5변형 완전 단조(원본 해상도 32.23 → 22.88 dB)
- 공개 배포본이 fp16 한계를 넘는다는 **존재 증명**(AngelSlim 3B-AWQ 0.96배)
- 여유가 순전파 한 번에 계산된다 — 정의

**주변부** — 흔들려도 핵심이 서는 것들
- 증류 손실의 인과(단일 시드·단일 계열) · 처방의 실용성(bf16 커널 성숙) · 도구 설계 선택

> **실증 신호 (2026-09-15).** 최근 약점 7건 중 핵심을 때린 것은 3건이고 셋 다
> **같은 채널**(Table 1의 측정 조건 혼입)이었다. 그 채널은 자동 검사로 막혔다.
> 표본이 7건이라 단정하지 않되, 기록해 둔다.

## 닫힘 — 자동 검사가 재발을 막는다

| # | 약점 | 막는 장치 |
|---|---|---|
| C1 | 문서 숫자가 산출물과 다름 | `verify_claim_provenance.py` `values:` |
| C2 | 한 표/문단의 숫자가 **다른 조건**에서 옴 (해상도·dtype·표본 수) | 같은 스크립트 `sources:`/`allow_differ:` — 이유를 쓰게 강제 |
| C3 | 같은 수치가 여러 문서에 흩어져 **한 곳만 고침** | 같은 스크립트 `docs:` `stale:` |
| C4 | bf16 활성이 NaN인데 **측정값으로 기록** | `profile_other_vlm_families.py` — 비유한 값이면 예외 |
| C5 | `from_pretrained`가 조용히 **랜덤 초기화** | `probe_vision_tower_direct.py` strict 적재 + `check_weights_loaded` |
| C6 | 디스크 스킵 기록이 **실패 사유를 덮어씀** | `profile_other_vlm_families.py` — 기존 `failed` 보존 |
| C7 | **정정한 값이 다른 자리에 남음** (캡션·주석·다른 장·코드) | `audit_numbers.py` + `number_registry.json` — 정정 박스와 본문을 구분해 **본문에 남은 폐기값만** 오류로 올린다 |
| C8 | 조건 종속 값이 **조건 없이** 쓰임 (p50/최악, 평가/원본 해상도) | 같은 스크립트 `watch:` — 값은 맞으나 조건 병기가 필요한 것으로 경고 |

**검사기 자신의 회귀 시험**: `docs/claim_provenance_regress.yaml` (반드시 종료코드 1)

## 한계 — 9장에 적고 더 방어하지 않는다

| # | 한계 | 왜 닫지 않는가 |
|---|---|---|
| L1 | **단일 시드** — 5변형 정확도 순위를 주장하지 않음 | 5변형 × 3시드 ≈ 32일 |
| L2 | **단일 모델 계열** — 손실 설계 축은 Qwen2.5-VL에서만 | 다른 계열 학습이 필요 |
| ~~L10~~ | ~~「단일 가변 시퀀스」 계열 밖에서 실측한 적이 없다~~ | **닫힘 (2026-09-18)** — 조사 밖에서 **Pixtral-12B**(Mistral, 독립 아키텍처, 같은 가변 시퀀스 설계)를 쟀다. **여유 35.91배로 안전**하다. 따라서 *"가변 시퀀스면 붕괴한다"*는 **기각**이고, 설계는 **전제**일 뿐 원인이 아니다. 원인은 그 설계 위의 **증폭기**(`down_proj` 849행, 노름 중앙값의 9.33배, 32/32 블록 최상위)이며 4장이 이미 규명했다. 다만 Pixtral 활성(1,824)이 고정 입력 계열(155~232)의 8배라 **설계가 크기를 밀어 올리기는 한다** |
| ~~L11~~ | ~~실측 위험 사례가 Qwen2.5-VL 하나 — 증폭기가 고유한가~~ | **닫힘 (2026-09-18).** 6계열의 MLP 출력 투영 행 노름을 쟀다(`probe_amplifier_across_families.py`). **증폭기 비로도 붕괴를 예측할 수 없다** — `Qwen2-VL-2B-AWQ`가 **14.80배로 가장 큰데 여유는 3.88로 안전**하고, Qwen2.5-VL은 9.33배에 여유 0.95로 붕괴한다. **역전이다.** Spearman(비, 여유) = −0.429 (n=6). 남는 결론은 **활성 = 증폭기 × 입력**이고 입력 쪽은 가중치로 안 보인다는 것 — 4장이 이미 규명한 바다. **이것이 논문의 논지를 세 번째로 뒷받침한다**: config로도, 설계로도, 가중치로도 예측할 수 없으니 **재야 한다** |
| L13 | **여유 상속을 한 계열에서만 확인했다** (2026-09-18) | 기반 모델과 공식 AWQ의 여유가 **자릿수까지 같음**을 Qwen2.5-VL 3B에서 확인했다(68,608 / 0.95 / 0.76). 원리상 `vision_excluded` 양자화면 어느 계열에서나 성립해야 하나(비전 가중치를 안 건드리므로) **다른 계열에서 확인하지 않았다.** 닫으려면 InternVL이나 LLaVA의 기반·AWQ 쌍을 재면 된다(각 15분). 원리가 자명해 보이지만 **자명해 보이는 것이 틀렸던 사례가 오늘만 셋**이다(DLA·타일 수·동적 판정) |
| L12 | **"재는 것 말고 방법이 없다"의 반대 방향을 안 밝혔다** (2026-09-18) | 세 예측 시도가 전부 실패했다는 것은 **처방을 정당화하지만**, 동시에 *"그럼 사전 선별이 원리적으로 불가능한가"*라는 질문을 연다. 우리는 **세 후보를 반증했을 뿐** 불가능성을 보이지 않았다. 남은 후보(예: 활성 통계를 쓰는 저비용 대리 지표)를 탐색하지 않았으므로 **"예측 불가"가 아니라 "이 셋으로는 안 된다"**로 적는다. 닫으려면 별도 연구가 필요하다 |
| L3 | **처방의 수명** — bf16 커널이 성숙하면 **1.34~1.38배** 비용이 소멸 | 본 논문에 불리하므로 더 분명히 적는다. **다만 속도 말고 두 근거가 더 있다.** (i) **정밀도** — fp16은 가수 10비트, bf16은 7비트라 범위 안에서는 fp16이 **8배 정밀**하다. 규격이므로 커널이 성숙해도 사라지지 않는다. (ii) **DLA** — FP16·INT8만 지원하므로 bf16이 선택지가 아니다. **단 이는 AGX Orin·Orin NX 한정이고 본 연구 대상인 Orin Nano에는 DLA가 없다**(2026-09-18 확인) — 상위 모듈로 확장할 때의 근거로만 쓴다. 성숙해도 "목적이 안전에서 성능으로 옮겨갈" 뿐이다 |
| L4 | **게이트 보정이 합성 교란 기반** | 자연 점 5개로 교차 확인했으나 여유 1.73~50.86 구간이 비어 있다 |
| L5 | **조사 분모가 자기선택** — 후보 281개 중 읽힌 197개 | 84개는 config 접근 불가 |
| L6 | **적재 실패 저장소 6개** | **`transformers`를 올리면 상당수가 열린다 — 안 연 이유는 측정 일관성이다.** 스크립트 15개가 4.49 내부 API에 묶여 있고 지금까지의 모든 측정이 4.49에서 나왔다. 올리면 한 논문에 두 버전 수치가 섞인다(얻는 것 모델 6~7개 < 잃는 것 전체 일관성). **"파편화가 결과"라는 논거는 27개 중 4개라는 비율이 뒷받침하는 것이고, 개별 저장소를 안 뚫은 것과는 별개다** — 후자를 전자로 정당화하지 않는다 |
| L7 | **대형 저장소 2개 미시도** | 19~40 GB, 디스크 |
| L8 | **`MARGINAL_HEADROOM = 1.25`는 측정이 아니라 추론** | 실측 전이 1.00~1.05 + 모델 내 편차 15~20%에서 유도 |
| L9 | **문서의 논거와 코드 구현의 불일치는 자동으로 못 잡는다** | 값 검사도 provenance 검사도 통과한다 — 문서 안에서는 일관되기 때문이다. 2026-09-17에 둘이 나왔다(게이트 통계량: 문서 최악·코드 p50 / DLA: 문서는 bf16 불가·도구는 모두에게 bf16 권고). §3.5에 "논거가 바뀌면 그것을 구현한 코드를 본다"를 규칙으로 적었으나 **사람이 지켜야 하는 규칙**이다 |

## 분류 규칙 (새 약점이 나오면)

1. **자동으로 잡을 수 있는가** → 검사기에 규칙을 넣고 **닫힘**. 회귀 시험도 같이 넣는다
2. **닫으려면 32일·하드웨어·새 계열 학습이 필요한가** → **한계**. 9장에 적고 끝낸다
3. **한 시간 안에 닫히는가** → **열림**에 넣고 비용을 적는다

**자동화할 수 없는 부류가 남는다.** A100의 fp16·bf16 처리량이 규격상 같다는 것, 문항이
장면별로 뭉쳐 독립 표본이 79라는 것 — 도메인 추론으로만 보인다. 이건 줄일 수는 있어도
없앨 수 없으므로, **원장에 "미분류" 칸을 두지 않는다.** 나오면 위 셋 중 하나로 보낸다.
