## 1. 내용 규칙

1. **결과만 쓴다.** 측정을 위한 우회, 실패한 시도, 재시도, 도구 오류, 사전 등록·기준 변경 경위는 본문에 쓰지 않고
   개요(§6)·약점 장부에 둔다(사용자 2026-10-22·11-06 「원고에는 결과만 기록, 실패는 기록하지 않음」).
   「처음에는…」「…할 수 없어」「…로 대체해」가 보이면 다시 본다.
   - **환경 의존 변동은 쓰지 않는다** (2026-11-10 12:06 KST, 사용자 「환경에 따른 ±2 dB는 부록 표에서 생략」): 원고 수치는 한 환경(TF32 끔)의 값만 쓰고,
     부록 표에는 소프트웨어 판만 적는다. 옛 환경 값, TF32 켬 값, 환경 사이 차이는 개요에만.
     TF32 설정(「TF32를 끄고 계산」, TensorRT 엔진의 「TF32 허용·끔」 포함)도 원고에 쓰지 않는다(2026-11-10 12:08·12:10 KST 사용자 「생략」).
   - ~~예외: 결과를 본 뒤 판정 기준을 바꿨다면 처음 기준과 그 수치는 본문에 남긴다(working_agreement ②).~~ **2026-11-10 사용자 「원고에는 결과만」**: 기준 변경 경위와
     처음 기준의 수치도 개요에만 둔다(working_agreement ②의 예외보다 우선).
   - 범위 진술(무엇을 측정하지 않았는가)은 한계 서술에 한 구절로만.
2. **주장은 「원본 출력을 지킨다」.** 모든 모델(SDXL VAE·FLUX·Qwen·Gemma)에서 「잔차 재조정은 fp16 상실을 없애고 원본 모델의 fp32 출력을 지킨다」.
   과제 정확도·화질 지표는 주장으로 쓰지 않는다(2026-11-04 23:16). 지표가 원래와 같다는 것은 쓰되 「화질이 더 좋다」로 쓰지 않는다.
3. **강조할 이점의 순서**: 출력 보존(fp32 등가) → bf16을 지원하지 않는 하드웨어 → 속도(부수적). 지연은 측정 그대로(bf16 대비 1.07배) 쓴다.
4. **「처음·유일」 금지.** 문헌 조사를 하지 않기로 했으므로(2026-11-03) 신규성은 이미 인용한 문헌과의 차이로만 쓴다.
5. **불리한 결과를 그대로 쓴다.** 래퍼 검증 「최소 0.9994, 743/799가 0.9999 이상」, 지연비 1.07배 등.
6. **공식 보고 여부**는 모델 카드와 기술 보고서를 모두 확인한 뒤에만 쓰고, 확인한 출처를 적는다.
7. **통계량과 표본을 항상 병기**한다(장수·해상도·형식·스텝·p50/최악·평균/중앙).
8. **원인 귀속은 분리해 확인한 것만** 단정한다. 분리하지 않은 것은 「…로 본다」로 쓴다.
9. **단일 실행 결과로 순위를 주장하지 않는다.** 수치로 쓴다.

## 2. 범위 (2026-11-04~11-06 결정)

- **주 기여 네 가지**: ① SDXL-VAE-FP16-Fix 대비 이점, ② Draw Things 대비 이점, ③ 공식 모델 교정(Qwen2.5-VL-3B·Gemma 4), ④ (R) 자동 도구(`auto_resid`).
- **교정은 (R) 하나.** (P)·(G)·(A)는 원고에서 뺀다(개요에만).
- **eps는 (R) 정의의 한 줄**(「정규화 eps를 c²배 한다」)로만. eps 미조정 배포·적용 조건은 개요에만.
- **학생 모델 전부 생략**(증류·다섯 변형·λ 스윕·활성 프로파일 등).
- **주 데이터는 DriveLM**(val CAM_FRONT 799장, 공식 처리기 기본값). RealWorldQA 결과는 원고에 쓰지 않는다(개요에만).
- **공식 저장소 설정 그대로**: 공식 가중치, 처리기 기본값, sdpa, 공식 채팅 템플릿, 탐욕 생성 + 반복 벌점 1.05. 다른 것은 fp16 형식과 Gemma 경로 (ii)뿐.
- **Gemma 4**: 경로 (ii)(승격 없는 배포 경로)와 경로 (i)(공식 transformers, fp32 승격)을 구분해 쓴다. 종단 생성은 하지 않았다.
- **Qwen 보존·문장 일치는 799 전체 값만** (2026-11-10 16:00 KST, 사용자 「228장과 571장 결과 생략, 799장 결과 작성」): 무교정 fp16이 유지한 228장(문항)·상실한 571문항의 부분 표본 값은 원고에 쓰지 않는다(개요에만).
- **COCO 표는 잔차 재조정 「모두 fp16」 한 행만** (2026-11-10 17:00 KST, 사용자 「생략으로 진행」): 「인코더 fp32 + 잔차 재조정 디코더 fp16」 행(63.2 dB)과 그 원인 서술은 쓰지 않는다 — 디코더 단독 정확도는 5.1.1절 생성 잠재 표가 보인다.
- **진단은 「측정용 100개 → 오버플로 지점·최댓값 M → c」로 서술** (2026-11-10 17:15 KST, 사용자 「초과 비율 측정이 아닌 c를 측정하는 것으로 서술 검토」 → 「이 방향으로 진행」): 초과 비율과 상실률 「예측」은 원고에 쓰지 않는다(72.7%·57%·55%, 「일곱 조건의 예측 대 실제」 없음). 결과는 측정용 최댓값 M과 c, 평가 입력의 bf16 최댓값과 그 c배(목표 32,752 이하), 무교정·잔차 재조정 fp16의 실제 상실로 쓴다. 그림 5-2 = `fig_calib_c`. 아래 ① 「일치로 서술」은 이 결정으로 대체됨.
- **원고 전체 검토 반영 (2026-11-10 17:05 KST, 사용자 결정 세 가지)**: ① 진단 서술 「일치로 서술 (권장)」 — 초과 비율은 같은 입력을 bf16으로 측정한 값이므로 「상실률을 예측하였다」로 쓰지 않고 「같은 입력의 bf16 측정 초과 비율이 실제 fp16 상실과 일치하였다」로 쓴다. Qwen은 측정용 100장의 초과 비율 57%를 함께 적는다. 「예측」은 「bf16 측정으로 fp16 상실을 미리 판별」의 뜻으로만. ② TensorRT 부하 빌드 「생략 (권장)」 — 다른 작업이 GPU를 쓰는 중에 빌드한 무교정 엔진(563장, 70.5%)은 원고에 쓰지 않는다(GPU 전용 재빌드 550장·68.8%만). ③ 「재구성으로 변경 (권장)」 — VAE의 인코딩→복호는 「재구성」(COCO val2017 재구성, 표 [COCO-재구성]). 「복원」은 1/c·×8로 크기를 되돌리는 뜻으로만.
- **용어 (같은 검토)**: 「상실하다」는 타동사로 「출력을 상실하였다」(「N장이 상실하였다」 쓰지 않음); 표기 자릿수에서만 같은 값은 「표기 자릿수에서 같았다」(「동일하였다」 쓰지 않음); Gemma 4의 최댓값 지점은 「풀링 뒤 스케일 곱(×√1152)」(「표준화의 곱셈」 아님); 진단 명칭은 「표현 범위 여유 진단」(제목의 「표현 범위 기반 오버플로 진단」은 그대로); 측정하지 않고 분리하지 않은 원인은 「~로 본다」; 표·그림 번호 뒤 조사는 합본 스크립트가 번호 읽기에 맞춘다(`fix_particles`).
